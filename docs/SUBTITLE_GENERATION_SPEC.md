# 字幕生成システム 完全設計仕様書

## 概要と設計思想

音声書き起こし結果から、映画・放送業界基準に準拠した字幕を生成するシステム。
「字幕は意味の単位で切る。行は文法の単位で折る」を原則とする。

### 現行システムの根本的欠陥

| 欠陥 | 症状 | 原因 |
|------|------|------|
| カットポイントがルールベース | 文の途中で字幕が切れる | `calculateBreakScore` は文字数と句読点のみ判定 |
| 行分割がN回個別AI呼び出し | 前後の文脈がゼロ・遅い | `createSubtitleEntry` 内でループ毎にHTTPコール |
| 検証がタイミングのみ | 意味的に不自然な字幕が素通り | `validateSubtitleTiming` は数値検証のみ |

---

## 新アーキテクチャ: 3フェーズAI処理

```
Input: words[] (タイムスタンプ付き)
          │
          ▼
┌─────────────────────────────────┐
│  Phase 1: AI一括セグメント分割   │  ← 全テキストを1回のAI呼び出しで処理
│  (カットポイント決定)             │    ルールベースを廃止
└─────────────────────────────────┘
          │  segments[]: string[]
          ▼
┌─────────────────────────────────┐
│  Phase 2: タイムスタンプ割当     │  ← words[]とセグメントテキストをマッチング
│  (CPU処理、AIなし)               │
└─────────────────────────────────┘
          │  SubtitleEntry[] (timing付き)
          ▼
┌─────────────────────────────────┐
│  Phase 3: AI一括行分割最適化     │  ← 全字幕を1回のAI呼び出しで処理
│  (行分割決定)                    │    個別呼び出しを廃止
└─────────────────────────────────┘
          │  SubtitleEntry[] (lines付き)
          ▼
┌─────────────────────────────────┐
│  Phase 4: タイミング調整         │  ← 既存ロジック
│  (CPU処理)                       │
└─────────────────────────────────┘
          │
          ▼
┌─────────────────────────────────┐
│  Phase 5: AI包括検証             │  ← 全字幕を1回のAI呼び出しで検証
│  (品質保証)                      │    新規追加
└─────────────────────────────────┘
          │  ValidationResult
          ▼
        Output: SubtitleGenerationResult
```

**AI呼び出し回数の比較:**
- 旧: N回（字幕枚数分の個別行分割）+ 0回検証
- 新: 3回固定（セグメント分割 + 行分割 + 検証）

## Phase 1: AI一括セグメント分割

### 目的

「どこで字幕を切るか」を意味単位で決定する。
音声認識テキスト全体を1回のAI呼び出しで処理し、全カットポイントを返す。

### 入力

- 全書き起こしテキスト（句読点除去済みの生テキスト）
- 設定: `maxCharsPerLine`, `maxLines`, `language`
- 計算された最大文字数: `maxCharsTotal = maxCharsPerLine × maxLines`

### AIへの指示（日本語プロンプト要点）

```
以下の書き起こしテキストを字幕用にセグメント分割せよ。

制約:
- 1セグメントの最大文字数: {maxCharsTotal}文字
- 各セグメントは意味的に完結した単位であること
- 文の途中でセグメントを切らないこと

セグメント分割の優先順位:
1. 文の完結点（文末表現）で切る
2. 接続詞・接続助詞の前で切る（「しかし」「そして」「だから」等）
3. 引用・会話の区切りで切る
4. 読点の前後で切る（ただし意味のまとまり優先）

絶対禁止:
- 助詞の直前・直後で切らない（〜は、〜が、〜を、〜に等）
- 修飾語と被修飾語を分断しない
- 固有名詞を分断しない
- 1セグメントが {maxCharsTotal} 文字を超えないこと

出力形式（JSONのみ）:
{"segments": ["セグメント1テキスト", "セグメント2テキスト", ...]}
```

### 出力

```json
{
  "segments": [
    "映画のマーケットをまず調べるじゃないですか",
    "世界のランキングとかを見ていくと",
    "英語か英語じゃないかでもう興行収入がまるで違うと",
    "それこそパラノーマルアクティビティとかって千何百万で",
    "あれ100億あげてるのよ"
  ]
}
```

### エラーハンドリング

AIが不正なJSONを返した場合、または `maxCharsTotal` を超えるセグメントが
含まれる場合は、**ルールベースのフォールバック**（現行 `groupWordsIntoSubtitles`）
を使用してリトライする。

## Phase 2: タイムスタンプ割当

### アルゴリズム

AIが返したセグメントテキストと `words[]` のタイムスタンプを対応付ける。

```typescript
function assignTimestamps(
  segments: string[],
  words: TranscriptionWord[]
): SubtitleEntry[]
```

**マッチング戦略:**
1. セグメントテキストを文字に分解
2. `words[]` を順番に処理し、累積テキストがセグメントと一致するまで進める
3. 一致したら `words[first].start` → `words[last].end` をタイムスタンプとして使用
4. 完全一致しない場合（音声認識の微妙な差異）は fuzzy マッチング（レーベンシュタイン距離）

**重要:** AIは単語の順序を変えず、テキストの追加・削除もしない。
タイムスタンプ割当は必ず元の `words[]` の順序に従う。

## Phase 3: AI一括行分割最適化

### 旧設計の問題点

- 字幕1枚ずつに個別AIコール → 100枚なら100回のHTTPリクエスト
- 前後の字幕を知らないため文脈的に矛盾する改行が発生する場合がある

### 新設計: バッチ処理

全セグメントを1回のAIコールで処理する。

**プロンプト形式:**

```
以下の{N}個の字幕テキストそれぞれに対して、最適な改行位置を決定せよ。

設定:
- 最大文字数/行: {maxCharsPerLine}
- 最大行数: {maxLines}
- 言語: 日本語

改行ルール（詳細は後述）:
[既存の詳細ルール...]

入力:
1: 映画のマーケットをまず調べるじゃないですか
2: 世界のランキングとかを見ていくと
3: 英語か英語じゃないかでもう興行収入がまるで違うと
...

出力形式（JSONのみ）:
{
  "results": [
    {"index": 1, "lines": ["映画のマーケットを", "まず調べるじゃないですか"]},
    {"index": 2, "lines": ["世界のランキングとかを見ていくと"]},
    {"index": 3, "lines": ["英語か英語じゃないかで", "もう興行収入がまるで違うと"]},
    ...
  ]
}
```

### 行分割の詳細ルール（日本語）

#### 絶対禁止事項

| 違反 | 悪い例 | 理由 |
|------|--------|------|
| 助詞で行を開始 | `彼` / `は優しい` | 「は」は前の語と一体 |
| 主語と述語の分断 | `私は明日` / `学校に行く` | 意味のまとまりが崩れる |
| 修飾語と被修飾語の分断 | `低予算の` / `映画` | 形容詞は名詞と同一行 |
| 固有名詞の分断 | `パラノーマル` / `アクティビティ` | 作品名は不可分 |
| 数量表現の分断 | `100` / `億円` | 数字と単位は同一行 |

#### 推奨カットポイント（優先順）

1. **文の完結点** — 文末表現（「〜た」「〜です」「〜ます」「〜よ」「〜ね」「〜な」）の後
2. **接続詞の前** — 「しかし」「そして」「また」「だから」「でも」の直前
3. **引用の境界** — 「〜と言った」「〜と思った」の後
4. **長い接続助詞の前** — 「〜けど」「〜から」「〜ので」「〜のに」の直前
5. **意味のある読点** — 意味の単位が完結している読点位置

#### 視覚的バランス原則

- 2行の場合: 上行≦下行（ボトムヘビー、下が長い or 同等）
- 極端な不均衡を避ける（上3文字/下20文字など）
- 文字数が1行に収まる場合は改行しない

#### 英語の行分割ルール

- 冠詞（a/an/the）で行を開始しない → 前行末に
- 前置詞で行を終わらない → 次行頭に
- 動詞と目的語を分断しない
- ハイフネーション: 語が長すぎる場合のみ、音節境界で

## Phase 5: AI包括検証

### 目的

生成された全字幕を通しで見て、品質問題を検出する。
タイミング検証（既存）とは独立して実行する。

### 検証項目

#### A. カットポイント検証

| 問題 | 例 | 重篤度 |
|------|-----|--------|
| 文中断切り | `#3: 「英語か英語じゃない」` `#4: 「かでもう」` | error |
| 主語と述語の分断 | `#7: 「それが」` `#8: 「本当に難しくて」` | error |
| 助詞・接続詞残し | `#12: 「でも」`（1語だけ） | warning |
| 不自然な長さ | `#15: 1文字` or `#16: maxCharsTotal超過` | warning |

#### B. 行分割検証

| 問題 | 例 | 重篤度 |
|------|-----|--------|
| 助詞で行開始 | `「パラノーマル」\n「アクティビティが」` | error |
| 固有名詞の分断 | `「パラノーマルアク」\n「ティビティ」` | error |
| 視覚的不均衡 | 上2文字/下18文字 | warning |

#### C. 前後の連続性

| 問題 | 例 | 重篤度 |
|------|-----|--------|
| 意味的断絶 | 前字幕と全く関係ない内容が次字幕に | info |

### 検証APIレスポンス

```typescript
interface SubtitleValidationResult {
  issues: SubtitleValidationIssue[]
  overallScore: number  // 0-100
  passedCount: number
  warningCount: number
  errorCount: number
}

interface SubtitleValidationIssue {
  subtitleIndex: number    // 1始まり
  type: 'cutpoint' | 'linebreak' | 'continuity' | 'length'
  severity: 'error' | 'warning' | 'info'
  message: string
  suggestion?: string      // 修正後の推奨テキスト
  affectsIndices?: number[] // 関連する他の字幕インデックス
}
```

## UI仕様

### SubtitleGenerator コンポーネントの変更点

#### 生成フロー表示

字幕生成中は以下のステップインジケータを表示:

```
[1/5] セグメント分割中... ████░░░░░░ 40%
```

ステップ:
1. AIセグメント分割
2. タイムスタンプ割当
3. 行分割最適化
4. タイミング調整
5. 品質検証

#### 検証結果UI

生成完了後、問題がある場合:

```
品質検証結果  ●エラー 2件  △警告 5件

#3  [error] 文中断切り
    「英語か英語じゃない」 → 次の字幕と結合推奨
    
#7  [error] 固有名詞の行分断
    「パラノーマルアク|ティビティ」→ 1行に
    
#12 [warning] 行の視覚的不均衡
    上2文字/下16文字 → 改善推奨

[全エラーを修正] [結果を無視してダウンロード]
```

#### 既存の字幕編集UI

変更なし。検証結果で指摘された字幕番号をクリックするとその字幕の
編集フィールドにスクロールする機能を追加。

## 移行方針

1. 新APIは `?mode=ai` クエリパラメータで有効化（既存の動作を破壊しない）
2. AIキーが未設定の場合は旧ルールベースにフォールバック
3. Phase 1/3/5 のいずれかが失敗した場合も前フェーズの結果を保持して継続
